## Data flow

1. User fills ID, name, description per business (C2 form). "Extract draft" sends `{descriptions:[{id,name,text}]}` for businesses with all three; blank set or non-slug IDs are rejected locally with no request.
2. `client.extract` (same origin as `VITE_API_BASE_URL`, only `Content-Type` header, no credentials). Response `mode` must equal `VITE_DATA_MODE` (C1) or it is discarded.
3. On success the review panel shows the original text, proposed values, supporting quotes and MISSING badges, and `draftToForm` loads the proposal into the editable form (`apply_draft`). Nothing is confirmed.
4. `validateForm` (C2) gates "Confirm scenario": missing capacity/coordination or the owner's own estimate keeps it disabled and lists blockers.
5. `runConfirm` posts `{scenario}`; success -> `set_confirmed` for the same `version` only.
6. Any later edit bumps `version`, clearing `confirmed` and `result`.

Errors: network, timeout, v1 envelope (code, fields, request id), malformed body and mode mismatch all render as alerts. The form is never modified by a failure and no draft is substituted.

## Staleness design

Two layers: (a) a `seq` counter plus `AbortController` in `begin()`; (b) an effect on `version` that aborts in-flight requests and bumps `seq` on every form change. A response is applied only if its id equals the current `seq`. The test "ignores a late extraction response" edits the name while extraction is pending, then releases the response; the draft is not applied and the user's value stays.

## Assumptions and limits

- Starting extraction replaces the form with the proposal (stated next to the button). Edits are preserved on failures, not on a successful re-extraction.
- The review shows the last proposal as received; it is not re-highlighted as the user fills values (the form's own errors do that).
- A draft with fewer than 3 businesses is padded with blank ones, which stay invalid.
- `/confirm` is treated as authoritative; its returned scenario is stored without field-by-field comparison with what was sent.
- Not checked in a real browser. Playwright NOT RUN.

## Judge questions

1. Can the model confirm a scenario? No. Extraction responses are rejected if the draft has `confirmed`, null values stay blank, and only the explicit button calls `/confirm`, with a payload the user has seen and can edit.
2. What if the user types while extraction runs? The effect on `version` aborts the call and increments the request id; a late response is ignored (tested).
3. What if the extractor omits a number? It stays `null`, shown as MISSING, and the form field is blank. Validation rejects blank required fields, so it never becomes zero effort.
