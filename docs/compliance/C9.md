## Design

What animates: an arrow that is new, or has another provider or other minutes, compared with the previous result shown in the same graph (or, for the what-if graph, the original result). Arrows that disappear just vanish. Self-work (shown on boxes) is text and changes at once. Nothing moves: node positions come only from business order, never from the result, and a test compares positions across very different results.

The effect is one opacity fade on the arrow group and its label. It starts from the real position and ends fully visible after 450 ms. It cannot hide a cost, an error or the provenance badge because those are outside the graph and never get the class; the browser test checks that the mode banner and certificate have opacity 1 and the text list and table are already present while an arrow is still fading.

Verified gate (`NetworkGraph`): no problems from `buildGraph` (all providers and deliverables exist in the confirmed scenario) and `checkCertificate(result.certificate).ok`. That is a shape check of what the server sent. It does not recompute digests or arithmetic and is not a signature.

Reduced motion: `usePrefersReducedMotion` reads the media query and listens for changes; `useEnteringEdges` returns an empty set when it is on, so no class is ever applied. The CSS also sets `animation: none`, so a missing JS check still cannot animate.

Data flow: `OptimizePanel` or `Simulation` pass `scenario` and `result` (already mode-checked and shape-checked by `ApiClient`) -> `useEnteringEdges` compares with `state.result` (updated during render when the prop changes, so the first painted frame already has the fade class and nothing flashes) -> `edges` with `className: "tm-edge-enter"` and `data.entering` -> a timer (450 ms + 150 ms) clears the set. A newer result replaces the set immediately; the timer is cleared on every change and on unmount.

Pan and zoom: React Flow keeps its viewport while `nodes` and `edges` props change; `fitView` only runs at the first draw. The graph component is the same instance across results, so the user's view survives a re-optimize (tested: zoom in, run again with a different result, transform unchanged). Pan is by dragging; scroll-wheel zoom stays off so the page can scroll; double-click zoom is off. On a touch screen, dragging inside the 320 px-high graph pans the picture instead of scrolling the page; the rest of the page scrolls normally.

Keyboard: `Controls` renders `button`s labelled "zoom in", "zoom out", "fit view" in that tab order with the normal focus ring (`showInteractive={false}`, fit with no animation). The picture itself still has no tab stops.

## Assumptions and limits

- The MVP contract is exactly three businesses (`docs/contracts.md`); five is the optional extension. Nothing here shows or assumes a deployed backend that accepts five. The screen's input form still has three businesses; the five-company case exists only through stubbed responses in tests.
- With five companies the layout widens and the fit is padded more. Two arrows between the same pair bow apart, but their labels sit close together (see the screenshot). It is readable, not ideal; the text list is the complete record.
- The 450 ms fade is the only motion. There is no animation on removal, on node text, or on numbers.
- A what-if that removes all arrows (no exchange) animates nothing, by design.
- The "verified" gate relies on the server's certificate being genuine; the browser cannot check that.
- Complexity: `changedExchangeEdges` is O(assignments x deliverables), at most 6 x 6.

## Judge questions

1. Why only a fade? A moving graph invites reading meaning into the movement. A single short fade marks exactly the arrows that changed and nothing else, and the numbers, certificate and banner stay still.
2. How do you know the animation only follows verified changes? It requires the result's ids to match the confirmed scenario and a well-formed server certificate. This is a shape check, so the claim is "the server said it verified this", not that the browser recomputed it.
3. What does a user with reduced motion get? The same arrows and list immediately, with no class and no animation. The browser test emulates the setting and checks the computed animation is `none`.
4. Does it scale to five companies? In a stub-driven browser run it draws in about a tenth of a second and zooms instantly. That says nothing about a backend for five; the MVP is three.
