## Data flow

`OptimizePanel` gives `Savings` and `Certificate` the confirmed scenario and the server `Result` (already mode-checked and shape-checked by `ApiClient.optimize`, C4).

- `Savings` renders only server numbers. The browser derives only percentages: `percent(part, whole)` = `floor(part*1000/whole)` as tenths, returns null unless `whole > 0` and `part >= 0`. 2/3 shows 66.6%, never 66.7%. Hours come from `formatDuration` (exact or minutes, C2).
- `findInconsistencies` re-adds the server's own numbers (gross = baseline - production, net = baseline - effort, effort = production + coordination, per-business sums = totals, net >= 0). It shows an alert on mismatch. It is a display guard, not the verification.
- `Certificate`: infeasible -> "None, no allocation to verify". Otherwise `result.certificate` null -> red "NOT verified". Present -> `checkCertificate` requires: schemaVersion "1", two 64-hex digests, verification "valid", non-empty string assumptions, at least one check, every check named and `passed === true`, and no unknown fields. Any failure lists the problems and nothing is shown as verified.
- Provenance: fixture mode -> "SIMULATED (fixture mode). Not a live verification." Live -> "live backend". `ApiClient` already discarded responses whose mode differs from the configured mode (C1), so the label is reliable.
- `ExplainSection`: separate button, `POST /explain {scenario, result}`, request-id guard and abort; reset when the result or scenario changes. Success text is rendered as plain text under "Generated text … the figures are authoritative". Failure shows its own alert and leaves everything else untouched.

Errors: explain failures are isolated; certificate problems never hide the numbers but remove the "verified" claim; inconsistent numbers raise an alert.

## Assumptions and limits

- Percentages are truncated, so they can read up to 0.1 point lower than a rounded value.
- Net savings percentage uses the total baseline; if baseline is 0 it shows "n/a".
- The browser does not check that digests match the data. A syntactically valid certificate from a wrong or hostile server would still display; trust rests on the backend.
- The `/explain` text is untrusted model output: rendered as text only, length-capped at 5000 characters.
- Not viewed in a real browser; Playwright NOT RUN.
- Complexity: O(businesses) per render.

## Judge questions

1. What does the certificate prove? That the server recomputed the arithmetic and constraints under the supplied estimates. It is not a signature, not tamper-proof, not an identity credential and not a profit or quality guarantee; the UI says so next to the digests.
2. Why show a figure at all when the certificate is missing? The numbers remain readable, but the panel states they are NOT verified, so the user is not told something false.
3. Why truncate percentages? Rounding up could overstate savings; integer truncation avoids floating-point error and never inflates.
4. What if the explanation disagrees with the table? The table is authoritative and the prose says so. `/explain` is optional and its failure changes nothing else.
