## Data flow

Confirmed scenario (`state.confirmed`, set by C3) -> "Optimize" -> `client.optimize({scenario})` -> `{result, mode}`. Mode must equal `VITE_DATA_MODE` (C1); `isResult` must pass -> `set_result(forVersion)` -> panel renders from `result` only.

`buildGraph`: for every assignment, find the deliverable (owner, service), check the provider exists, make a `Line`. Provider == owner -> self-work (node annotation). Otherwise an edge `provider -> owner` with id `edge-<deliverableId>`. Unknown deliverable/provider ids or a deliverable assigned twice yield `problems` and the component shows an alert instead of a graph. The graph never adds an assignment that the result does not contain.

Errors: network/timeout/envelope/mode mismatch/malformed result show "Optimization failed" with request id; nothing replaces the missing result.

Staleness: `seq` + `AbortController`, and an effect on `version` that aborts and bumps `seq` on every form change; a reducer guard (`set_result.forVersion`) is a second line of defense. Edits also clear `confirmed`, so Optimize is disabled until re-confirmation.

## Assumptions and limits

- Numbers are displayed from the backend result; the frontend does no optimization or savings arithmetic except the display percentage (integer division, one decimal; omitted if baseline is 0). Totals are not recomputed or checked against assignments here.
- Parallel edges between the same pair overlap visually in React Flow; the text list is the complete record.
- Node layout is a fixed ellipse by business order; graph is not draggable. Graph is not keyboard-explorable, hence the text mirror.
- The page was not viewed in a real browser; jsdom does not lay out React Flow, so only data (nodes, edges, list) is tested, not pixels. Playwright NOT RUN.
- Complexity: graph build O(a*d) over at most 6 assignments and 6 deliverables.

## Judge questions

1. How do you know the graph is not invented? `buildGraph` only maps `result.assignments`, requires ids to exist in the confirmed scenario, and shows an alert on any inconsistency. no_exchange yields zero edges (tested).
2. Why do edge ids use deliverable ids? Two exchanges can share provider, owner, service and duration; the deliverable id is unique, so ids and React keys cannot collide (tested).
3. What happens if the user edits while optimizing? The request is aborted, a late reply is ignored by `seq` and the reducer guard, and the old result and confirmation are cleared (tested).
4. Is "62.5%" a profit figure? No. It is gross labor-minutes saved over baseline under the supplied estimates; the panel says it is not profit or a quality guarantee.
