## Data flow

Input: text fields -> `scenarioReducer` (`edit_business`) -> `ScenarioForm` (strings). `validateForm` runs on every form change (`useMemo`) and returns `{errors, scenario}`. `scenario` is a v1 `Scenario` (integer minutes, `confirmed: true`) only when there are no errors; otherwise null and field errors are rendered next to inputs. The UI blocks Continue on null.

Duration rules (`parseDuration`): accepts `2.5`, `2.5h`, `90m`; up to 6 decimals; requires `fraction*60` to be an exact integer, so `0.001` is rejected rather than rounded; max 1,000,000 minutes; estimates must be >= 1, capacity/coordination >= 0. `formatDuration` shows hours only when minutes is divisible by 3 (finite decimal), otherwise minutes (e.g. `10m`), so display never rounds. A test round-trips 0..2000 minutes.

Blank estimate = unsupported service, never 0. The owner's own estimate for its required service is mandatory, mirroring the backend's `422 MISSING_BASELINE` (the backend stays authoritative). ID rules copy `contracts/scenario.schema.json` (`^[a-z0-9]+(?:[-_][a-z0-9]+)*$`, <= 64) plus uniqueness. The 3-business MVP size is enforced by the fixed three forms.

Errors: validation only; no network calls in this prompt, so no AWS or backend error paths exist here.

## Judge questions

1. Why not round hours to minutes? Rounding before the capacity or no-worse-off checks could turn an infeasible plan feasible. Inputs that are not whole minutes are rejected (`parseDuration`, tested with `0.001`).
2. Does the sample loader change the shared fixture? No. `loadCanonicalForm` uses `structuredClone`; a test edits state and confirms the imported fixture is unchanged.
3. Does a blank estimate mean zero? No. It means unsupported; zero is rejected for estimates (`kind: "positive"`), and the owner's own estimate is required.
