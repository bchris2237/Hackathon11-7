## Design and tradeoffs

| Decision | Why | Tradeoff |
|---|---|---|
| Telemetry is **allowlist based**: fixed event names, fixed field names, and a string value must be a short token (`[A-Za-z0-9._:/{}()-]`, no `://`) | A blacklist of "bad strings" cannot keep up with what people paste. With an allowlist a description, a business name, a signed URL (it has `?` and `=`) or a sentence cannot be written even if a caller passes one by mistake | A new field needs a code change. A legitimate free-text value is replaced by `[invalid]` |
| The written line also goes through the B8 `redact` | A credential that happens to be made of token characters (an AWS key id, a 40-character secret) passes the character test, so the second layer catches it | Pattern based, best effort |
| Model usage is summed per request in a context variable and reported on the request line; the adapter runs in a **copy of the request's context** | One Logs Insights query then gives tokens per route. A thread pool does not carry context variables by itself, so without the copy every model call would show as zero (a test fails if the copy is removed) | A small amount of plumbing in `_call_adapter` |
| Tokens the SDK did not return are `null`, never `0`; a failed call adds no tokens and no "unknown" | "Unknown" and "none" are different facts and a cost estimate built on zeros would be silently wrong | A consumer must handle null |
| Cost model in `Decimal`, one product of an assumption and a rate per line, rounding only when printing | Money should not accumulate float error; each line can be checked by hand | More verbose than floats |
| The model refuses volumes beyond the first Lambda / API Gateway pricing tier | The price table is only valid below those thresholds; beyond them the answer would be wrong, not just rough | It cannot estimate a very large workload |
| Prices live in code with their date and source, and a test checks the worksheet and the model agree | The worksheet cannot silently drift from the arithmetic | The test cannot know whether AWS changed its prices. Recheck before relying on it |
| Two Claude rates are modelled (`us.` profile $1.10/$5.50, `global.` $1.00/$5.00) plus Nova 2 Lite | The deployed profile is the regional one, which the Price List charges 10% more for; the owner may want to choose | More rows to maintain |

## Data flow

`App.handle` opens `request_usage()` (a context variable) and dispatches. `_call_adapter` submits the adapter with `contextvars.copy_context().run`. The Bedrock client calls `record_model_call(...)` after each `Converse` (ok or error), which adds to the request's `RequestUsage`.
When the response is built, `emit(log, "request", ..., **usage.snapshot())` writes one allowlisted line. Bedrock calls also write their own `bedrock_call` line with the AWS request id.
Cost path (offline): `Assumptions` plus `Prices` go to `estimate_monthly_cost`, which returns a `CostBreakdown`; `python -m backend.telemetry` prints the tables; `docs/aws-costs.md` quotes them and a test keeps them equal.
Errors: telemetry never raises (`emit` swallows its own failures); the cost model raises `CostModelError` for out-of-range assumptions.

## Algorithm assumptions and complexity

Per line: `monthly cost = quantity x rate`, with quantity derived from `sessions x calls per session x per-call amount`. Lambda duration = `billed seconds x (memory MB / 1024) x rate per GB-second`; log storage = `ingested GB x retention days / 30 x rate` (average GB held);
DynamoDB reads round up to 4 KB units. All O(number of steps). Assumed, not measured: everything marked "assumed" in `docs/aws-costs.md` section 2 (the optimizer, explain and proposal token counts, log bytes, page sizes, session counts).

## Judge questions with grounded answers

1. **How do you know your logs do not leak customer text?** The emitter is an allowlist: only listed events and field names are written, and a string value must be a short token with no `://`, so a sentence, a name or a signed URL is replaced before it is serialised. The line is then redacted again. A test runs a full stubbed extraction and asserts none of the description sentences, names, credentials, client addresses or URLs appear anywhere in the captured log, and another asserts every line contains only allowlisted fields. It is a code guarantee for our own log lines, not for libraries that log elsewhere.
2. **What does this cost to run?** In the worksheet's assumptions: about $0.91 for 100 demo sessions and about $61 for 10,000, on the regional Claude Haiku 4.5 profile; about $0.57 and $27 on Nova 2 Lite. Roughly 98% of the busy figure is model tokens. Rates are from AWS's own Price List files read on 2026-11-07, free tiers are excluded, and most usage numbers are assumptions; only the extract call is measured.
3. **How do you know the token numbers are right?** For the one measured call, our recorded 694 input and 386 output tokens equal Bedrock's own CloudWatch metrics for that model. Everything else in the worksheet is labelled assumed. When the SDK returns no usage the field is null and the worksheet says UNKNOWN, never zero.
4. **What happens if a model call fails?** The request line shows `modelCalls` 1, `modelErrors` 1 and zero tokens (a failed call is not billed for tokens), and the `bedrock_call` line carries the AWS error code. On this account that is how the Marketplace permission problem showed up.
5. **Is it deployed?** See "Live verification" below for exactly what was and was not checked on AWS.
